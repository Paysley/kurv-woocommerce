= 1.0.5 — 2026-08-14 =

* Fixed: the card fee disclosure could fail to appear at checkout. The totals
  rows rely on the woocommerce_review_order_after_order_total hook, which a theme
  shipping its own checkout/review-order.php can omit — and a fee disclosure must
  not vanish because of a template override. If the rows do not render, the
  disclosure now appears in the payment method description instead. Only one of
  the two is ever shown: the totals template runs before the payment methods, so
  the plugin knows by then whether the rows appeared.
* Fixed: readme claimed refunds are performed from WooCommerce admin, which
  stopped being the default in 1.0.4.

= 1.0.4 — 2026-08-14 =

Dual pricing disclosure, and a refund safety fix.

Refunds
* Fixed: a serious hazard for merchants who refund in the Kurv portal. Marking
  the WooCommerce order Refunded afterwards sent a second, full-value refund to
  the API — there is no duplicate-refund guard on that endpoint, and a partial
  refund in Kurv was followed by a full refund here. The new "Manage refunds in
  Kurv" setting (on by default) makes the status change a record-keeping action
  only, and hides WooCommerce's Refund button so it cannot be used by mistake.
  Disable the setting to refund through WooCommerce as before.

Dual pricing / card fee
* Added: optional disclosure of the card fee at checkout, for merchants whose
  Kurv account has dual pricing enabled. The customer sees the base price, the
  card fee and the total they will actually be charged, before paying.
  Configurable percentage and labels, so the wording can match local
  requirements.
* IMPORTANT: the percentage is used for display only and is never added to the
  amount submitted to Kurv. Dual pricing is applied on Kurv's side and cannot be
  suppressed per request, so adding it here as well would charge the fee twice.
  The plugin deliberately does not call WC_Cart::add_fee(), because that would
  raise the cart total and therefore the amount submitted.
* Added: the order total is now brought up to the amount Kurv actually charged,
  once payment succeeds. Previously an order recorded the base amount while the
  customer was charged the base plus the fee, so every order, customer
  confirmation email and revenue report understated the sale. The fee line is
  built from the amount reported by Kurv, never from the configured percentage,
  so it is exact for any percentage and any rounding rule. It runs before
  payment_complete(), so the confirmation email shows the real total, and is
  guarded so a callback and a browser return arriving together cannot apply it
  twice.
* Added: an order note if Kurv ever reports a charge lower than the order total,
  rather than silently adjusting the books downwards.
* Note: on the block checkout the disclosure appears in the payment method
  description rather than as separate total rows — injecting custom rows into the
  block totals needs a Store API extension, which is not done here.

= 1.0.3 — 2026-08-14 =

Production hardening.

* Changed: the API timeout is cut from 70 seconds to 20. These calls can run on
  the checkout thread, so in the worst case — timeout plus two rate-limit
  retries — a customer could previously sit on a spinner for over three minutes.
  Override with the new kurv_api_timeout filter if a site needs longer.
* Added: kurv_api_base_url filter, so a store can be repointed at a different
  API host without waiting for a plugin release. Prompted by the live hostname
  fixed in 1.0.2: with this in place, that outage would have been a one-line
  snippet rather than a release.
* Fixed: 12 places read $result['response']['code'] and $result['body'][...]
  directly. When the API returned anything that is not a JSON object — an HTML
  error page, a 502 from a proxy, an empty body — json_decode() produced null
  and those reads emitted PHP warnings, on the checkout page in some paths. All
  API responses now go through Kurv_API::unpack(), which always yields an int
  status code and an array body.
* Fixed: customer personal data is no longer written to the debug log. Payment
  and customer payloads had been logged verbatim, putting email addresses, phone
  numbers and billing addresses into plain-text files under wp-content/uploads.
  Those fields are now masked as [redacted:N], preserving whether a field was
  populated without disclosing the value.
* Changed: the logo asset drops from 535 KB to 70 KB. It embedded a 1344x1132
  PNG that renders at 104 px at most; the raster is now 320 px. Rendering is
  unchanged. The embedded image is only a background gradient, so a proper
  vector export would take this to a couple of KB — worth doing separately.

= 1.0.2 — 2026-08-13 =

* Fixed: the live API base URL was https://live.kurv.app, a hostname with no DNS
  record. Live mode could never connect — every checkout on a live API key
  failed with "cURL error 6: Could not resolve host: live.kurv.app". The live
  base URL is now https://api.kurv.app. Sandbox was unaffected.

= 1.0.1 — 2026-08-13 =

Hardening ahead of WordPress.org approval: clears every finding in the Plugin
Check report and fixes several correctness bugs in the payment path. 1.0.0 was
submitted but never published, so no store is running it.

Payment reliability:
* Fixed: the payment result is now received on a dedicated server-to-server
  endpoint (/wc-api/kurv/). Previously response_url pointed at the thank-you
  page and the result was read with get_query_var(), which cannot see a POST
  body — so Kurv's callback was effectively ignored and an order only completed
  if the customer's browser made it back.
* Fixed: an order is no longer marked failed when the browser return carries no
  payment result. Any request to the thank-you URL with a valid token but no
  response parameter used to fail the order, including Kurv's own callback.
* Fixed: successful payments now go through WC_Order::payment_complete() instead
  of a manual update_status() call, so the paid date, transaction ID, stock
  reduction and the woocommerce_payment_complete hook all fire correctly.
* Added: scheduled reconciliation. Orders still awaiting payment are re-checked
  against the Kurv API after 10 minutes, 1 hour and 6 hours. Reconciliation can
  only move an order forward to paid, never fail it.
* Added: Kurv_API::get_payment_request() (GET /payment-requests/{id}), and the
  Kurv transaction ID is now stored on the order so reconciliation has something
  to look up.
* Fixed: applying a payment result is now idempotent, so the callback and the
  browser return racing each other cannot double-process an order.
* Fixed: payment tokens are compared with hash_equals() and no longer depend on
  fields taken from the callback payload — a payload omitting the currency could
  previously never be verified.

Correctness:
* Fixed: get_country_code() is now static. It was an instance method called via
  ( new self() ) on every checkout, and each throwaway gateway instance
  re-registered every constructor hook — including the refund handlers.
* Fixed: undefined array offset warning in the order meta box when the gateway
  settings option does not yet exist.
* Fixed: refunds against an order with no Kurv payment ID now return a clear
  error instead of calling the API with an empty ID.
* Fixed: API responses that are not valid JSON no longer emit warnings when the
  plugin reads the response body.
* Fixed: get_cart_items() no longer fatals when a product has been deleted since
  the order was placed.
* Fixed: the 429 retry now makes at most 3 requests total, matching its
  documented behaviour (it previously made 4 and slept up to 7 seconds).

Performance:
* Changed: product sync runs through Action Scheduler instead of blocking the
  request. Saving a product made up to three API calls with a 70-second timeout
  each, and checkout synced every unsynced product inline.

WordPress.org Plugin Check:
* Fixed: exception messages passed through esc_html() (3 errors).
* Fixed: translators comments added to two placeholder strings (2 errors).
* Fixed: $_GET['section'] unslashed and sanitized.
* Fixed: global classes prefixed — WC_Kurv is now Kurv_Payments_Gateway and
  WC_Kurv_Blocks is now Kurv_Payments_Blocks. Class files renamed to match.
* Fixed: removed the discouraged load_plugin_textdomain() call.
* Fixed: readme "Tested up to" raised to 7.0.
* Fixed: removed .DS_Store files and hardened .gitignore. Releases should be
  built with git archive so untracked files cannot be packaged.
* Fixed: block checkout JS used the wrong text domain, so one string could not
  be translated.
* Changed: meta box CSS moved out of an inline <style> block into an enqueued
  stylesheet.

Other:
* Changed: plugin headers declare Requires Plugins: woocommerce and WC tested up
  to 11.0.
* Changed: the order meta box uses the public OrderUtil API to detect HPOS
  instead of a class under WooCommerce's \Internal\ namespace.
* Changed: checkout overlay strings are translatable and set via the DOM rather
  than interpolated into markup.
* Removed: the Payment Link Expiry setting, which had no effect — the code
  behind it is commented out pending confirmation of the format Kurv accepts.
* Fixed: the settings screen showed the checkout URL as the payment response
  URL; it now shows the real callback endpoint.

= 1.0.0 — 2026-04-01 =
* Initial release of Kurv Payments for WooCommerce.
* Full rebrand from Paysley; all references updated.
* PHP 8.1 minimum requirement; strict types and typed properties throughout.
* WooCommerce 8.0+ minimum; all deprecated WC function calls updated (new WC_Order, WC_Logger, magic property access).
* Fixed: $this->supports declaration was being overwritten — refunds support now correctly declared alongside products.
* Fixed: process_payment() exception handling — unhandled exceptions no longer crash the checkout page.
* Fixed: $order->save() added after all update_meta_data() calls so meta persists correctly.
* Fixed: woocommerce_thankyou_{gateway_id} hook replaces woocommerce_before_thankyou (previously fired on every order's thank-you page).
* Fixed: add_post_meta() replaced with update_post_meta() for product sync (prevented duplicate meta rows on repeated saves).
* Fixed: Content-Type header corrected to 'application/json' (was incorrectly cased as 'Application/json').
* Fixed: wp_hash() replaces md5() for payment token generation (uses WordPress secret key via HMAC-SHA256).
* Fixed: is_wp_error() checks added on all Kurv API calls to handle network failures gracefully.
* Fixed: URL injection in category and customer search queries — rawurlencode() + add_query_arg() used throughout.
* Fixed: WooCommerce Blocks integration $name mismatch (was 'Paysley', must match gateway id 'kurv') — blocks checkout was silently non-functional.
* Fixed: wp_set_script_translations() corrected to use proper script handle and languages path.
* Fixed: time() cache-busting on block script replaced with plugin version constant.
* Fixed: process_full_refund now listens to woocommerce_order_status_changed (3 params) instead of deprecated woocommerce_order_edit_status (2 params).
* Improved: Explicit Test Mode toggle added to settings — replaces brittle API key prefix detection ('py_live').
* Improved: Separate Live API Key and Test API Key fields; settings validation checks the active key based on current mode.
* Improved: Full refund failure now writes a clear order note instead of an unreliable admin meta box redirect.
* Improved: HPOS (custom_order_tables) compatibility declared for WooCommerce 8.x+.
* Improved: Dead code removed — getProductTax() (defined but never called), get_order_prop() (WC 2.x shim no longer needed), global $woocommerce (unused).
* Improved: Typos fixed in order notes and meta values ("successfull" → "successful", "succes" → "success").
* Improved: check_and_create_product_category() consolidated — 'No Category' fallback replaced with translatable 'Uncategorised'.
* Improved: Plugin header now declares Requires at least, Requires PHP, WC requires at least, and WC tested up to.
* Added: index.php silence file preserved in all directories.
